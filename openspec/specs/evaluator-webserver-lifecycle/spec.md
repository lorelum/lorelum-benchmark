## Requirements
### Requirement: Diagnostic evaluator WebServer uses an isolated port per attempt

Each diagnostic attempt MUST give its evaluator WebServer an independent port so
consecutive attempts do not conflict. The runner MUST either allocate a free
port and manage the server with a controlled supervisor, or inject a dynamic
port into the evaluator run. Port allocation, server launch, readiness, and
teardown MUST fail closed with a stable redacted category when they cannot be
confirmed.

#### Scenario: Consecutive attempts use distinct ports
- **WHEN** two diagnostic attempts run sequentially against the same candidate
- **THEN** each attempt uses a different WebServer port and the first attempt's
  server does not block the second

#### Scenario: Port allocation fails
- **WHEN** a free port cannot be allocated for the attempt
- **THEN** the attempt records `execution-failed` with a stable redacted reason
  and produces no semantic or quality conclusion

### Requirement: Evaluator child processes are cleaned up on failure and timeout

The evaluator WebServer MUST be terminated by the supervisor when the evaluator
exits, fails, or times out, and the evaluator process tree MUST be terminated
on timeout or abnormal failure. Normal evaluator exit relies on the evaluator
and its Playwright workers to self-recycle. Cleanup MUST use the repository's
verified process-tree termination on Windows (`taskkill /T /F`) and Linux
(recursive parent scan + SIGTERM). Cleanup MUST be verified with a bounded
port-release probe; if cleanup cannot be confirmed, the attempt MUST be
recorded as `execution-failed` rather than entering comparison.

#### Scenario: Evaluator timeout cleans up the WebServer
- **WHEN** an evaluator exceeds its attempt budget
- **THEN** the runner terminates the evaluator process tree including the
  WebServer and records a stable timeout category without a semantic result

#### Scenario: Cleanup cannot be confirmed
- **WHEN** the runner cannot confirm the WebServer port was released after the
  attempt
- **THEN** the attempt is recorded as `execution-failed` and does not enter
  semantic, Practice, or joint-pass comparison

### Requirement: Startup failures use stable redacted categories

The runner MUST classify WebServer launch failure, dependency failure, port
conflicts, and evaluator timeouts with stable redacted failure categories and
MUST NOT read them as candidate or Practice failure. The failure category MUST
be recorded on `evaluation_status=execution-failed`, and the categories MUST
NOT include port numbers, private paths, or command output.

#### Scenario: Server launch failure is not a semantic result
- **WHEN** the WebServer fails to start for an attempt
- **THEN** the attempt records a stable redacted category and produces no
  semantic, Practice, or joint-pass fields

### Requirement: Public-only workspace and private evaluator boundary is preserved

The WebServer lifecycle change MUST NOT modify candidate public material,
Practice, Oracle, quality rubric, or private evaluator semantics. Candidate
`public/starter/app/playwright.config.ts` and `vite.config.ts` MUST remain
unchanged and their snapshots MUST NOT be regenerated by this change.

#### Scenario: Candidate files unchanged
- **WHEN** the runner manages the WebServer lifecycle
- **THEN** candidate `public/starter/app` files and snapshots remain unchanged
  and the evaluator receives the server URL through the declared environment
  channel
