# Spec Delta

## Purpose

定义需要真实用户确认和独立操作授权的编码 Agent 参与自主 Pack 对照时，如何保持交互真实、私有评测隔离、配对可解释及不确定结果可见。

## ADDED Requirements

### Requirement: 真实交互与独立授权

系统 MUST 在互动式编码 Agent 执行前向用户展示待确认计划及其身份，并以真实用户决定确认准确版本；资料披露、文件修改和命令执行 MUST 使用各自适用的明确授权，不得由模型或自动测试替身代替真实决定。计划变更、撤销或冲突 MUST 阻止使用失效确认继续执行。

#### Scenario: 确认和授权有效
- **WHEN** 用户已审阅准确计划版本，分别授予执行所需的权限和资料披露
- **THEN** 系统可以在对应权限范围内执行，并记录绑定的计划、决定和操作身份

#### Scenario: 决定缺失或失效
- **WHEN** 用户拒绝、撤销、未确认当前版本或未授权操作
- **THEN** 系统不执行未经授权的后续操作，并保留相应的失败或未执行状态

### Requirement: 用户可操作的验收路径

系统 MUST 提供用户可实际操作的验收入口，使用户能够提供任务或调整意见，查看完整计划及版本、执行权限、可得的进度和候选差异，并在运行结束后分别查看受测 Agent 的检查／报告与 Benchmark 独立功能验收结果。缺失、取消和失败 MUST 对用户可见；模拟决定或替身模型结果 MUST NOT 被描述为真实用户或真实模型验收。

#### Scenario: 用户调整并验收
- **WHEN** 用户在入口中提出调整、确认更新后的计划并独立授权受控执行
- **THEN** 用户能看到实际调整后的计划、执行结果和独立验收状态，且系统分别保留交互、功能和质量证据

#### Scenario: 工作流未完成
- **WHEN** 用户未确认、撤销授权或执行／验收过程缺少证据
- **THEN** 用户能看到未完成步骤及原因，不将测试替身的成功代替实际交互结果

### Requirement: 自主知识对照和可比较性

系统 MUST 为安装 Pack 和空 Store 两组提供相同的任务、starter、模型、一般工具能力、规则和预算，且仅以声明的 Pack 安装状态作为预期处理差异。Agent MUST 自行决定是否查询、查询内容及是否读取；系统 MUST NOT 预先选择查询、强制查询或注入选定 Practice。无法提供相同的自主查询能力、有效授权或独立 Store 时 MUST NOT 将结果认定为有效 Pack 对照。

#### Scenario: 可用的两组运行
- **WHEN** 两组的输入身份与隔离均得到核验，且知识调用能力等价
- **THEN** 系统分别保留两组的运行和可见检索证据，不因某组未查询而伪造执行失败

#### Scenario: 调用无法完整观测
- **WHEN** 存在未覆盖的知识调用渠道
- **THEN** 系统将整体检索状态标记为不可判定并保留已观察调用，不单独因此否定其他条件满足的功能比较

#### Scenario: 交互或条件差异破坏可比性
- **WHEN** 两组真实用户决定、工具权限或初始配置使比较条件不再等价
- **THEN** 系统记录差异与不可比较原因，不由自动流程补造或替代用户决定

### Requirement: 隔离候选与独立语义验收

系统 MUST 将公开任务与 starter 作为编码 Agent 的任务材料；私有 verifier、oracle、评分和校准材料 MUST NOT 进入 Agent 工作区或模型输入。Agent 停止后，系统 MUST 使用独立、受控的任务 verifier 评估具有可核验身份的候选；Judge 自评 MUST NOT 代替功能语义验收。

#### Scenario: 独立 verifier 返回语义结果
- **WHEN** 已停止候选的身份有效且 verifier 正常执行并完成协议
- **THEN** 系统记录实际功能通过或失败，并将质量证据与交互状态独立报告

#### Scenario: 评估或执行不可判定
- **WHEN** 隔离、启动、通信、超时或 verifier 输出无法核验
- **THEN** 系统保留失败或不可判定状态，不把基础设施故障解释为语义通过或失败

### Requirement: 可追溯但不夸大的案例结果

系统 MUST 固定并记录足以重建和解释各运行的任务、输入、verifier、Agent、环境、模型、工具、Pack 与索引身份以及预算；MUST 保留全部计划运行和缺失原因。质量或成本不可用时 MUST 保留未运行或不可得，不得用零值或成功替代。正式 record 和真实模型运行须遵循各自授权与生命周期。

#### Scenario: 完整或部分结果
- **WHEN** 配对包含完成、拒绝、失败或缺失运行
- **THEN** 报告区分交互、执行、功能、检索与可选质量，保留计划分母，不将单一案例或 Agent 自评表述为 Pack 效果证明
