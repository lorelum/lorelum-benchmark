# Design

## Context

Issue #246；背景和目标见 proposal。Benchmark 的 `autonomous-pack` v2 将任务、可见输入、私有 verifier 和条件分开，但现有配对 runner、工具策略与执行环境绑定 Pi。`config-migration-v2` 是已有候选，公开题面和 starter 与私有 JSONL verifier 已存在；本案例复用，不重写该版本。

独立 Judge 工作流截至本提案：#64 与 #67 为 draft，#67 head `56c0794209277f34fa7906e5d5f63b9c8acd2be4`，base `d9a95413018b455c9b7343e43252cf795dfdfb73`。规划请求不提供工具；执行 action 仅支持 read、write、从宿主预先授权的固定命令列表按索引选择、done。`SandboxPort` 只暴露有限工具链和隔离副本，网络隔离且不提供宿主 Store。没有证据证明该 API 可以自主构造 Lore query/get；列出固定查询命令会预选查询，不满足本案例。WSL 中简单 `bwrap` 启动成功，仅是基础环境观察，不是完整隔离验证。

## Goals / Non-Goals

**Goals:** 在 Benchmark 中提供用户能亲自操作、观察并验收独立 Judge 工作流的案例：从用户请求、计划与调整到权限、修改、检查、报告和独立功能验收形成完整可见路径；同时实现受控的安装 Pack／空 Store 配对。使用公开契约而不是借助本机源码路径。

**Non-Goals:** 不将 Judge 自评作为功能 oracle，不把模型生成的计划条件当作用户要求，不创建正式 record，不改变旧案例和旧 runner 的含义；不实现未授权写回、跨进程恢复、发布或部署，不承诺不存在的资源硬限额。用户同意 Plan 不替代独立操作授权或模型披露。

## Decisions

1. **候选和基线**：复用 `incubator/autonomous-pack/config-migration-v2/public/task.md` 与 `public/starter/`；完成后才由既有受信任的 `private/evaluator` 通过 v2 verifier 协议独立评估。私有 evaluator、oracle、校准材料及条件映射不能进入 Judge 执行副本或模型。候选代码仍不可信。若需要修改题意或 verifier，创建新候选版本并遵守快照／记录生命周期，不能原地改有记录 revision。
2. **可重建依赖**：通过固定内容身份的 Judge 公开 package/protocol 及其依赖接入；#64/#67 尚未发布时不能冒称已发布。安装方式须能从受控来源重建并固定源／构建身份；禁止通过本机其他仓库的相对路径或内部源码 import。当前草稿 SHA 是调查参考，不是最终发布保证。
3. **职责与交互**：Benchmark 负责准备任务、条件和私有 verifier；宿主提供真实用户交互、明确的资料披露决定、展示计划及身份／revision、调整或拒绝、单独的文件／命令／披露授权和撤销。Judge 负责其公开工作流所定义的计划与受控执行。计划／用户决策不得由模型或脚本代替；自动化中的模拟决定只能用于离线管线测试。会话只在当前进程内，进程结束不承诺恢复。
4. **自主 Lore 的阻塞**：两组须在相同权限与机制下让受测 Agent 自己产生 query/get 的内容与时机，分别使用仅差指定 Pack 安装状态的独立 Store。当前 Judge 的固定命令 action 和 bubblewrap 挂载／网络限制尚未证明能满足此条件；先调查公开扩展点及上游可消费版本，确定兼容且授权明确的实现。若需要 Judge 上游扩展，先建立可追溯的上游依赖并等待真实能力，不引入私有 API、绕开沙箱、固定查询或注入预选 Practice，也不将未完成结果称为 Pack 对照。两组可见工具、一般说明、预算和规则相同；用户决策需真实独立取得并记录，若因决策差异或缺失破坏可比性，保留原因，不模拟相同确认。
5. **运行与证据**：针对 Judge 引入独立版本化执行 contract／adapter，而不是将 Pi 配置改名为 Judge。固定任务及 starter、verifier、Judge 及依赖、Lore/Pack/Store/index、运行环境、模型／端点身份、工具策略、预算、计划／授权和输出身份。两组隔离、不继承本机既有 Store 或凭据；Agent 停止后核验独立工作区身份再交给私有 verifier。记录完整计划分母、拒绝／撤销／中断／缺失；基础设施失败为 indeterminate 或 execution-failed，不等于语义 fail。普通轨迹无法覆盖全部 Lore 调用时，整体检索保持 indeterminate，保留可见行为；不因此自动排除功能比较。
6. **结果与质量**：功能以独立确定性 verifier 为准；Judge 内部检查／质量评论和任何外部质量证据分开，默认质量可为 not-run。`completed` 不意味着功能正确、计划效果或质量通过；未经对应证据不能计算质量分。人工交互成功和代码功能成功分别报告。公开结果只包含允许分享的身份与状态，原始轨迹、候选代码、私有 evaluator 和用户决定按授权受控保管，不提交仓库。
7. **验证**：保留两类证据：离线确定性模型／模拟用户驱动真实公开接口，只证明管线；实际用户交互验收需展示信息并记录真人决定，不能以替身替代。Linux 用真实隔离实现和独立 verifier 验证正反路径；模型或正式 record 不因本提案自动获授权。
8. **面向人的验收设施**：提供可直接启动的交互式宿主入口（首选终端交互，具体界面在实施计划中确定）。用户能输入任务或修改意见、查看实际完整计划和 revision、提出调整或拒绝、审阅执行权限并分别决定；执行时查看可得的进度、已做修改和检查，结束后查看 Judge 原始报告及 Benchmark 独立 verifier 结论。不可观察、取消、失败和限制必须显示，不能仅展示一条 pass。入口不得隐式调用真实模型或将自动化替身的确认标为真人。单案例检验 Judge 在该工作流中的实际可用性和效果，不代表该仓库所有功能、跨任务泛化或 Pack 因果效果已获证明。

新增 capability 的跨任务依据：真实计划确认与独立授权适用于任何需要人参与的编码 Agent；可操作的验收路径用于让任何此类 Agent 的实际行为可见；自主知识调用与条件一致性适用于任何互动式 Pack 对照；私有 verifier 隔离和独立语义验收适用于所有执行不可信候选的任务；身份、分母及不确定性是可复现报告的共同要求。具体案例、固定 Judge 草稿 SHA、环境、交互形式和预算仅在本设计及后续版本化配置中声明，不作为普遍限制。

## 计划中的文件职责与可变范围

- `schemas/`：仅在现有契约无法准确表达互动式 Agent 和结果时新增版本化声明；不能扩展旧版本语义冒充历史记录。
- `src/benchmark/autonomous-pack/`：按已确认设计新增 Judge 集成、配对执行、用户决策和证据映射；复用既有任务读取、快照与独立 verifier，不修改冻结的 v1/v2 helper 行为。
- `environments/`：固定实际 Judge 包／工具、Linux 沙箱、Lore、模型和 runtime 身份，并如实声明支持范围。
- `incubator/`：仅在需要记录该案例的条件和版本化配置时新增候选级材料；不覆盖 `config-migration-v2`。
- `docs/`：记录宿主操作、依赖、权限、交互及报告解读；不暴露私有材料或凭据。

## 等效实施计划（待用户确认）

1. **可消费依赖与环境**：从 Judge 上游固定实际可取得的 commit／公开包及其依赖，建立可重复安装和身份记录；不 import 其他工作树的内部路径。运行宿主位于 Linux，独立项目副本和沙箱必须满足上游文件系统约束；Windows 通过 WSL／Linux 使用，先做实际环境验证。已确认的 #67 草稿不是发行版本，最终来源和导入方式以实际可用产物为准。
2. **可见的 Judge 验收入口**：在 `src/benchmark/autonomous-pack/judge/v1/` 新增宿主及终端交互入口，使用 Judge 的 `PlanningSession` 和 `ControlledExecutionSession` 公开接口；在同一进程内呈现任务、披露决定、计划全文与 revision、用户调整、确认和独立操作授权。实际执行时展示当前可观察的阶段、候选 diff、Judge 检查／报告；不模拟用户授权、不声称跨进程恢复。Judge 版本、模型、权限与用户决定按受控记录绑定身份。
3. **可评估案例与双条件**：在 `incubator/` 新建仅含引用、场景及版本化设置的案例配置，引用现有 `config-migration-v2`，不复制或改写其公开／私有任务。每组从同一 starter 建立独立 Git 工作副本。确认真实 Lore 能力后分别准备安装 Pack 和空 Store，提供等价、Agent 可自行构造查询的能力；若现有上游公开契约不能安全支持，则在现有 Judge PR／后续授权的上游变更提供能力之前，该条件明确阻塞，不用固定查询或替身补齐。两组实际用户决策及影响如实记录。
4. **独立评价与展示**：在 `src/benchmark/autonomous-pack/judge/v1/` 接入已有 v2 任务解析、身份与私有 verifier；候选停止后核验身份，在受限环境独立验收。新增所需版本化 schema／结果记录并保留全部计划运行；用户界面分别展示计划质量和调整是否可见、执行和权限、Judge 检查、独立功能结果、可见检索、可选质量及成本。没有证据的维度显示未执行或不可判定，不能以 Judge 自评或模拟运行代替用户评价。
5. **实际验证**：自动化侧使用真实公开接口、Linux 隔离和确定性模型／模拟用户，覆盖允许、拒绝、计划失效、权限不足、撤销、检查失败、证据不足、两组 Lore 边界、候选隔离与 verifier pass/fail/indeterminate；模拟只证明管线。主线程在可用环境实际启动终端宿主并核对完整可见流程。需要用户本人操作或外部模型的验收明确区分，须在授权后进行并报告实际证据。最终运行 `bun run validate`、相关契约测试和 OpenSpec strict，保护历史记录与无关工作。

确认本计划不等于授权外部模型调用、Judge 上游仓库修改、发布或正式 record。实际 Lore 公开能力和可重建 Judge 包仍待验证；若调查结果要求改变接口、交互边界或对照范围，重新规划并取得用户确认。

## Risks / Trade-offs

- 两个草稿 PR 未合并发布且固定命令 action 无自主 query 参数；在上游可用且隔离边界明确前完整对照不可交付。不能通过 mock、复制源码或删掉 Pack 条件绕过。
- 人工审批过程可能不同且影响比较；须记录有效范围及排除原因。随机次序不能消除判断偏差。
- Linux bubblewrap 为共享内核隔离，Windows 不原生支持；在实际 Linux 上验证，不将 WSL 基础启动当成完整安全证明。当前上游报告 UTF-8 截断后返回字符串可能超过输出字节上限，不将其描述为严格字节上限。
- 不完整 trace 和未执行质量评估是合法的不确定／未运行结果；模型结果和一次案例不证明 Pack 效果。
