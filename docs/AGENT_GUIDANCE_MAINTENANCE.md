# Agent 纠错与规则维护

本指南只在根 `AGENTS.md` 的沉淀触发条件满足时使用；普通纠错仍先修正当前任务，不需要读完或维护本指南。

## 触发只启动评估，不自动写规则

持久化评估仅在以下任一条件满足时启动：

1. 同一错误模式在至少两个**有可核验证据的独立任务/对话**中出现；同一轮对话里的多次追问或同一任务中的重复解释不算两个独立样本。只统计当前可访问上下文或用户明确提供的证据；不可见历史不推测、不记账。
2. 一次高风险事件（例如 public/private 泄露、修改已有正式结果的冻结 revision、未经授权的模型调用/正式 record、不可逆破坏）显示现有规范缺失、冲突或无法被入口规则发现。
3. 用户明确要求把某个经验提升为可复用规则。

触发评估不自动新增规则：先检查已有规范并确定适用范围。若用户已明确要求沉淀，不再询问是否需要持久化；
若触发来自复发或高风险事件，且是否要提升为跨任务规则仍不明确，只询问这一未决点。一次纠正最多修正当前任务；
若失败只对当前 Issue/candidate/模型/实验成立，就留在该 Issue/OpenSpec/PR，不进入全局规则。

## 先诊断，再改唯一权威来源

每次评估按顺序完成：

1. 用一句话描述可复现的错误模式，不复制整段对话；区分用户纠正的事实、Agent 的错误推断和当前任务决定。
2. 搜索现有 `AGENTS.md`、适用的 stable spec/schema、skill/维护指南及当前 Issue/OpenSpec。确认是“缺规则”，还是已有规则被忽略、含糊、冲突、过时或放在不易发现的位置。
3. 若已有同义或冲突条款，优先合并、替换、收窄、删除或改入口；**不得为提高服从率而叠加同义措辞**。
4. 只有能脱离当前任务继续成立的 Agent 工作方式才进入通用 Agent 指南；benchmark 稳定契约归 stable spec/schema，领域方法归对应指南或 skill，实验决定归当前 Issue/OpenSpec。选一个 canonical source，其他文档只链接，不复制整段规则。
5. 新增规则默认采用“替换或合并”而不是净增。若确需新增，须说明现有条款为何无法承载，以及该规则覆盖的跨任务风险。`AGENTS.md` 只保留跨任务、高频或高后果、必须在每次相关任务开始前知道的规则；详细流程按需加载。

## 按范围路由，禁止错放

| 纠正/发现的范围 | 唯一落点 |
| --- | --- |
| 当前任务、candidate、模型或实验的决定 | 对应 Issue/OpenSpec；适用直接 PR 例外时写入当前 PR，不升成全局默认 |
| 维护文档事实错误或重复 | 修正 canonical source；必要时只更新导航链接，不把规则复制到其他指南 |
| 跨任务成立的 benchmark 契约 | 适用的 stable spec/schema，并遵守 Issue/OpenSpec 门禁 |
| 可复用 Agent 工作方式 | 高频/高后果的跨任务规则才进根 `AGENTS.md`；领域限定做法放对应指南或 skill |
| 工具或环境故障 | 修复工具、环境或操作指南；不要转写成 benchmark 规则 |

设计材料还须区分**说明示例**、**非规范性走查**和**验证证据**。只有预先声明的验收标准实际通过且有证据，才可称为验证；样例/走查数量不能代替通用性验证。
## 留证与回归

被接受的规则变更只在其已有 Issue、OpenSpec 或 PR 中记录：**错误模式 → 根因/规范缺口 → 唯一权威改动 → 回归场景与验证**。不另建逐次纠错台账，不记录普通纠错。

回归场景必须针对旧错误，并覆盖适用范围与非目标。优先用自动检查；如果无法自动化，在 PR 验证中做一次具体人工回放，并明确它只是流程回归，不夸称为通用性证明。若已有规则只是没被读取，回归需验证入口或适用范围修正，而不是只增加更多文字。

## 回归场景

规则升级的 PR 至少人工回放以下场景，并记录预期行为；它们是流程回归，不是用户行为统计：

| 场景 | 预期行为 |
| --- | --- |
| 用户只纠正一次、且只影响当前任务 | 修正当前输出；不新增全局规则、不建纠错日志 |
| 同一错误模式在两个有可核验证据的独立任务复现 | 启动沉淀评估；先定位已有规范并合并/替换，不直接追加同义条款 |
| 一次高风险事件暴露规范缺口 | 评估并补足唯一权威来源；验证 baseline、对照和非目标仍清楚 |
| 已有规则但 Agent 没遵守 | 检查冲突、适用范围、入口和篇幅；优先修复发现/理解问题，不复制规则 |
| 用户明确要求沉淀 | 不重复询问是否需要持久化；按请求评估适用范围并选择唯一落点，不把该请求解释成“以后每次纠错都记一条” |
## 文档治理检查

涉及维护指南的改动，快速核对：

- 是否有且只有一个 canonical source；导航页只负责指路。
- 规范要求、候选/单次实验决定、历史证据和示例是否清楚分层；编号案例不应伪装成通用证据。
- 是否存在过期日期/状态、互相矛盾的要求、重复全文、失效链接或已被后继规则取代却仍被导航为当前规则的内容。
- 是否可以通过删除/合并/链接缩短，而不是继续添加说明。

发现 stable spec 或 benchmark 契约冲突时，停止静默选边；按 `AGENTS.md` 的 Issue/OpenSpec 门禁修复权威来源。
