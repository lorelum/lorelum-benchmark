# React 项目操作来源权威

## 建议

1. 先区分项目操作的来源：导航和手动重载是前台操作，后台协调不是当前视图的结果权威来源。
2. 前台操作取得视图结果权威后，较早前台操作以及其后启动的后台协调都不得改变项目列表、加载或错误状态；成功和失败终态使用同一判定。
3. 在所有状态更新前依据来源和当前前台操作验证资格；请求代次、失效标记或等价的显式归属机制都可以，但不能把“最后开始的请求”当作唯一规则。

## 常见反模式

- 所有来源共用递增请求号，使较晚开始的后台协调覆盖用户刚完成的操作。
- 只阻断过期前台请求，却让后台协调的成功或失败更新当前视图。
- 只保护成功分支，后台协调失败时仍把错误写入前台视图。
- 仅按项目范围判定，遗漏同范围手动重载与操作来源之间的差异。
