# Import contacts from CSV

Complete the Python standard-library-only importer in `src/`. The entry point is `src/main.py`: it reads one JSON object per stdin line and writes exactly one JSON object per line to stdout, continuing until EOF. Do not write diagnostics to stdout. Each request is independent and has a `csv` string. Input requests are valid JSON objects with that field; no other input validation is required.

Interpret `csv` as comma-delimited CSV with double-quote quoting (including doubled quotes and quoted commas or newlines). The CSV is syntactically well-formed. Handle LF and CRLF line endings. Treat the first logical record as a header; it must be exactly `id,name,email` in that order, without trimming. An empty document or any other header produces `{"error":"invalid_header"}`.

For each subsequent logical record, numbered from 1 (not physical line number), produce either an accepted contact or an error, preserving input order within each list. A record with other than three fields has error `columns`. Otherwise trim surrounding whitespace from each field. If any resulting field is empty, report `required`. Otherwise if the email does not contain exactly one `@` with nonempty text on both sides, report `email`. Otherwise if the trimmed id was already accepted in this request, report `duplicate`. Validation is in that order; an invalid record never reserves an id. IDs and emails are case-sensitive. A blank CSV record is a record with zero fields and therefore has error `columns`.

For a valid header return `{"contacts":[{"id":...,"name":...,"email":...},...],"errors":[{"row":1,"code":"..."},...]}`. There are no other output fields. Process CSV records incrementally rather than splitting the text into lines or materializing all parsed rows; the input string and output lists may be held in memory. You may change the modules, but retain the CLI path and protocol. No third-party packages, network, or external services are needed.
