# 网关接 Nebula，顺手把计费和降级补上

把 Nebula 接进来。它说自己是 OpenAI 兼容，但接口文档里字段和鉴权跟 OpenAI 不一样，接的时候按测试里的 stub 实际行为来，别只凭名字套 OpenAI 那套。

主供应商遇到限流、5xx 或超时的时候，要能切到配置好的备选供应商把这次请求继续做完。重试可以有，但一个用户请求只能记一次账，重试和降级的用量不能重复算钱。

客户按租户结算，仓库里已经有每个租户的美元预算。请求要先占住额度，做完再按实际费用结算；余额不够要拒绝，并发请求不能把预算超掉。

重复请求要返回第一次的结果，不能重复调用供应商、不能重复计费；同一个幂等标识换了请求内容要报冲突。

流式请求如果响应头已经发出去了之后才失败，要发一个终止的 SSE 错误事件；只记上游已经报过的用量，别自己伪造最终 usage。

用量接口要支持按租户、模型、状态查。日志里带上租户、trace、重试次数这些字段。错误码按仓库里的接口文档来，别把上游原始报文原样透出去。改完跑下测试。
