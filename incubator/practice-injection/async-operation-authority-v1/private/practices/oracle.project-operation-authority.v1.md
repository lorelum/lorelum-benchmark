# React 项目操作来源权威

## 建议

1. 先区分项目操作的来源：导航和手动重载是前台操作，后台协调是后台操作。
2. 后台协调对当前视图生效，仅当它启动时没有前台操作在途，且距最近一次前台操作启动已超过 500ms；不满足任一条件时，其结果（成功或失败）都不得改变项目列表、加载或错误状态。
3. 前台操作取得视图结果权威：较早前台操作被取代后不得结算；成功和失败终态使用同一归属判定。请求代次、失效标记、时间戳窗口或等价的显式机制都可以，但不能把“最后开始的请求”当作唯一规则。

## 常见反模式

- 后台协调永远不生效：即使满足生效窗口条件也直接丢弃其成功结果。
- 所有来源共用递增请求号，使较晚开始的后台协调覆盖前台操作。
- 只保护成功分支：后台协调失败时仍把错误写入前台视图。
- 把后台协调的生效条件简化成“无任何请求在途”或“距任意操作足够久”，遗漏前台启动时间窗口。
